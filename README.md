# 다시봄 POS

다시봄 · 텔로미어 라이프스타일 &amp; 데일리 셀 케어 — **폰·태블릿·PC에서 바로 여는 웹 POS**입니다.
파일 하나(`pos.html`)만 있으면 인터넷 없이도 열리고, 구글 시트를 연결하면 여러 기기가 같은 품목·주문·**지점별 재고**를 보고 **본점에서 전 지점 판매 현황**을 모니터링합니다.

| 파일 | 역할 |
|---|---|
| `pos.html` | POS 본체. 외부 CSS/JS/CDN 참조가 전혀 없는 단일 실행 파일 |
| `leaflet-data.js` | 제품 설명서(리플렛) 원문 데이터 — 있으면 상품 상세에서 설명서가 열린다(없어도 POS는 그대로 동작) |
| `img/` | BV 배지가 찍힌 세트 상품 6종의 대표·키 이미지 편집본(대표 `{품목ID}.jpg` · 키 이미지 `{품목ID}-2.jpg`) |
| `apps-script.gs` | 여러 기기 동기화용 구글 Apps Script 백엔드 |
| `test_pos.py` | 자동 검증 스크립트 (문법·계산·비노출·CSV·정산·렌더링 스모크) |
| `README.md` | 이 문서 |

## 1. 폰에서 바로 열기

1. `pos.html` 을 폰으로 옮깁니다(카카오톡 "나에게 보내기", USB, 드라이브 등).
2. 파일 관리자에서 **Chrome 등 브라우저로 열기**를 선택합니다.
3. 주소창에 파일 경로가 보이면 정상입니다. **홈 화면에 추가**해 두면 앱처럼 열립니다.
   - Chrome: 오른쪽 위 ⋮ → 홈 화면에 추가
4. PC에서는 파일을 더블클릭하면 됩니다.

> 인터넷이 없어도 상품·주문·정산이 모두 동작합니다. 데이터는 그 기기의 브라우저에 저장됩니다.

## 2. 화면 구성

### 판매원 오픈 잠금 (첫 화면)
- 페이지를 열면 **다시봄 텔로미어 로고 + 현재 지점명(`다시봄 본점` 등) + 판매원 비밀번호 입력창**이 가장 먼저 나옵니다. (기본 켜짐)
- **초기 판매원 비밀번호는 `1111`** 입니다. **관리자 PIN(`0000`)과는 별개**로 동작합니다.
- 잠금이 풀리기 전에는 품목·가격·주문이 화면에 만들어지지 않고(HTML에 렌더링되지 않음) 판매 화면 자체가 숨겨집니다.
- 한 번 풀면 **같은 탭에서는 새로고침해도 다시 묻지 않습니다**(sessionStorage). 새 탭·새 창에서는 다시 묻습니다.
- 상단 오른쪽 **`🔒 잠금`** 버튼이나 `설정 → 판매원 오픈 잠금 → 지금 잠그기`로 다시 잠급니다(로그아웃).

### 고객 주문 화면 (기본)
- 상단 배너: **다시봄** 브랜드와 현재 지점, 웰니스 슬로건
- 상품 카드: 이미지 · 카테고리 · 상품명 · 한 줄 설명 · **소비자가** · `담기`
- 카드를 누르면 **상품 상세 페이지**가 열립니다
  - 큰 이미지, 카테고리, 상품명, 한 줄 요약, **소비자가**
  - 핵심 포인트 / 주요 성분·기능성 / 섭취·사용 방법 / 주의사항
  - 하단 고정 바에서 수량을 고르고 **장바구니 담기**
- 검색창(상품명·성분·설명), 카테고리 칩(**전체 + 지쿱 라인 6종 = 7개**)
- `전체` 를 고르면 상품이 라인별로 묶여 나옵니다 — **텔로메라 (9) · 제너럴 밸런스 (7) · 디엘릭서 (5) · 씨케이·활력 (2) · 지쿱카페 (2) · 의료기기 (3)** 처럼 라인 헤더와 품목 수가 먼저 보이고 그 아래에 카드가 깔립니다(괄호 숫자는 고객 화면에 노출 중인 품목 수). 라인 칩을 고르거나 검색어를 넣으면 섹션 없이 해당 결과만 보입니다.
- 주문서: 수량 +/−, 소계, 할인(정액·정률), **합계**, 지점, 판매 채널, 결제 수단, 고객명·연락처·배송지·메모
- `주문 확정` → **고객용 주문 확인서**가 열립니다 (종이 영수증처럼 **좁고 세로로 긴 모달**, 폭 최대 404px)
  - `카카오톡 복사` `문자 복사` **`이미지 저장 / 카톡 공유`** `인쇄` 버튼
  - **이미지 저장 / 카톡 공유**: 확인서를 **PNG 이미지**로 만들어 카톡 등 공유 시트로 바로 보내고, 지원하지 않거나 취소하면 `다시봄_주문확인서_{주문번호}.png` 로 저장합니다(5-2 참고)
  - 설정에 **입금 계좌**를 넣어 두면 확인서에 계좌·예금주와 `계좌번호 복사` 버튼이, **송금 링크**(https)를 넣어 두면 `송금 링크로 바로 보내기` 버튼이 함께 나옵니다

- 5회 틀리면 30초 동안 입력이 잠깁니다.

## 2-1. 제품 설명서(리플렛)

상품 카드를 누르면 열리는 **상품 상세**에서 **`제품 설명서 보기`** 버튼 한 번으로 지쿱 공식몰 상품 페이지의 **제품 설명 원문과 상세 이미지**를 그대로 펼쳐 봅니다. 고객 앞에서 화면으로 바로 보여 주는 용도입니다.

- **32품목 중 31품목**: 한 줄 소개 · 핵심 특징 · 원재료/성분 · 기능 정보 · 섭취·사용 방법 · 주의사항 · 보관 방법 · 섭취 대상 · 제품 정보 고시를 원문 그대로, **상세 이미지 746장**까지 보여 줍니다.
- **케어세르브 웨이브 플러스**: 공식몰 상세 페이지가 판매원 로그인에서만 열려, POS에 정리해 둔 설명 + 대표 이미지 1장과 `상세 설명서는 지쿱 공식몰 판매원 로그인 후 확인이 필요해요` 안내를 보여 줍니다.
- 비어 있는 항목(`""`, `[]`, `확인 불가`)은 억지로 채우지 않고 **해당 섹션을 생략**합니다.
- **출처 표기·공식몰 링크는 넣지 않았습니다.** 이미지 저장·공유 버튼도 없습니다.
- 상세 이미지가 품목당 최대 66장(전체 약 190MB)이라 모든 이미지를 **`loading="lazy"`(지연 로딩)** 으로 두었고, **대표 이미지**와 **상세 이미지** 섹션을 나눠 모바일에서 스크롤이 부드럽게 열립니다.
- 설명서 화면에서도 **폰 뒤로가기**는 상품 상세로 돌아오고(한 번 더 누르면 목록으로 닫힘), 상세에서 고른 **수량은 그대로 유지**되며 하단 `장바구니 담기`도 그대로 쓸 수 있습니다.
- 데이터 파일 **`leaflet-data.js`** 가 같은 폴더에 없으면 POS는 그대로 동작하고 `제품 설명서 보기` 버튼만 나오지 않습니다.

## 3. 지점

- 기본 지점: `본점`, `동탄점`, `온라인몰`
- 상단 가게 이름 아래 **지점 이름**을 누르거나, 주문서의 `지점` 칸에서 바꿉니다.
- 주문마다 **지점이 함께 기록**되고, 영수증·주문 내역·정산·CSV에 모두 표시됩니다.
- 유형이 **온라인**인 지점을 고르면 판매 채널도 온라인으로 바뀝니다.
- `설정 → 지점 관리` 에서 추가·이름 변경·삭제·기본 지점 지정이 가능합니다.

### 지점별 접속 링크 (`?branch=지점명`)
- `https://…/pos/?branch=본점` 처럼 주소 뒤에 **지점 이름**을 붙이면 그 지점으로 바로 열립니다. (지점 ID도 가능: `?b=b-dongtan`)
- 링크로 열면 **잠금 화면·상단 헤더·주문서·주문 기록**까지 그 지점으로 적용됩니다.
- `설정 → 지점 관리` 의 각 줄 **`링크 복사`** 버튼으로 지점별 주소를 복사해 카톡으로 나눠 주면 됩니다.
- 목록에 없는 지점 이름이 붙어 있으면(예: `?branch=평택점`) 오류 없이 **기본 지점**으로 열립니다. `다시봄 동탄점`처럼 가게 이름을 같이 보낸 링크도 인식합니다.

## 3-1. 판매원 오픈 비밀번호 · 지점별 비밀번호

관리자 → **설정** → **판매원 오픈 잠금**

- **판매원 오픈 잠금 사용** On/Off — 끄면 페이지를 열 때 바로 판매 화면이 나옵니다.
- **공통 판매원 비밀번호 변경** — 초기 `1111` (4~8자리 숫자). 지점 전용 비번을 정하지 않은 지점은 이 비번을 씁니다.
- **지금 잠그기** — 바로 잠금 화면으로 돌아갑니다.

관리자 → **설정** → **지점 관리** 의 **판매원 비번** 칸 → **`비번 설정`**

- 지점별로 4~8자리 **전용 비밀번호**를 정할 수 있습니다.
- 비우고 저장(또는 `전용 비번 지우기`)하면 그 지점은 다시 **공통 비밀번호**를 씁니다.
- 전용 비번이 있는 지점은 그 지점 링크(`?branch=동탄점`)에서 **전용 비번만** 통과합니다.

| 상황 | 동작 |
|---|---|
| 본점 링크 + 공통 `1111` | 열림 |
| 동탄점 링크 + 동탄점 전용 `2222` | 열림 |
| 동탄점 링크 + 공통 `1111` | 거부(전용 비번만 통과) |
| 본점 링크 + 동탄점 전용 `2222` | 거부 |
| 관리자 PIN `0000`을 판매원 칸에 입력 | 거부(관리자 PIN과 분리) |
| 5회 틀리기 | 30초 입력 잠금 |
| 비번을 바꿈 | 이미 열려 있던 탭도 다음에 다시 잠김 |

- 비밀번호는 **해시**로 비밀 저장소(localStorage)에만 저장되고 화면·영수증·공개 데이터에는 나타나지 않습니다.
- 비밀번호 설정은 **이 기기에서만** 적용됩니다(구글 시트로는 전송하지 않음). 여러 기기에서 같게 쓰려면 기기마다 한 번씩 설정합니다.

## 3-2. 재고 입출고 (지점별)

관리자 → **재고** 탭

- 재고는 **지점마다 따로** 셉니다. `본점`에서 판매해도 `동탄점` 재고는 줄지 않습니다.
- 처음 이 버전을 열면 **저장되어 있던 품목의 재고 값이 그 지점의 시작 재고**로 들어갑니다(주문·지점·설정·매입가는 그대로 유지).
- **위쪽 요약**: 판매 품목 수 · **부족(안전재고 미만)** · **품절** · 입출고 이력 건수
- **필터**: 지점 · 라인(카테고리) · 상태(정상/부족/품절) · 품목 검색
- **품목별 표**: 현재고 · 안전재고 · 상태 배지(정상/부족/품절) · 최근 변동 · **빠른 버튼 `입고` `출고` `조정` `안전`**

### 입출고 등록 (모달)

| 칸 | 내용 |
|---|---|
| 지점 | 재고를 바꿀 지점 |
| 품목 | 전체 품목(비노출 포함) |
| 구분 | **입고 · 출고 · 반품 · 손실 · 조정** |
| 수량 | 입고·반품은 더하고, 출고·손실은 뺍니다. **조정**은 입력한 수량을 **조정 후 재고**로 맞춥니다(재고 실사) |
| 안전재고 | 비우면 그대로. 이 수량보다 적으면 `부족`으로 표시 |
| 사유/메모 | 예: 거래처 입고, 재고 실사, 파손 |

- 출고가 현재고보다 많으면 **0에서 멈춥니다**(음수 재고를 만들지 않음).
- 안전재고 기본값은 **5개**이고, `안전` 버튼으로 품목·지점마다 따로 정할 수 있습니다. 0으로 두면 부족 표시를 하지 않습니다.

### 주문과 자동으로 연결

| 주문 상태 | 재고 | 이력 |
|---|---|---|
| 주문 확정 (접수) | 그 지점 재고에서 **차감** | `출고(판매)` + 주문번호 |
| 취소 · 환불 | **복원** | `입고(주문취소)` + 주문번호 |
| 취소·환불 → 다시 접수/결제완료/완료 | 재차감 | `출고(판매)` |

- 같은 주문을 두 번 취소해도 재고가 두 번 늘지 않습니다(중복 복원·중복 차감 방지).
- **재고를 아직 세지 않은 지점**은 그 품목의 기존 재고 값을 시작값으로 자동 생성한 뒤 차감하므로, 처음부터 재고를 넣어 두지 않아도 **판매가 막히지 않습니다**.
- 고객 화면에서는 **품절**이면 카드 사진 위에 `품절`, **안전재고 미만**이면 사진을 가리지 않도록 사진 아래 카테고리 태그 옆에 `재고 N개` 배지가 붙고, 상품 상세 위에 **현재 지점 재고**가 표시됩니다.

### 이력 · CSV

- **입출고 이력** 표: 일시 · 지점 · 품목 · 구분 · 변동 · 변동후 · 사유/메모 (최신 200건 표시)
- 지점 · 구분 필터, **`CSV 내보내기`**(필터에 걸린 전체 이력을 `다시봄_재고입출고_YYYY-MM-DD.csv` 로 저장)
- 이 기기에는 최근 **4,000건**까지 보관합니다(넘으면 오래된 것부터 정리). 더 오래 보관하려면 구글 시트 동기화를 쓰세요.

## 3-3. 본점 판매 모니터링 (지점 통합 현황)

## 4. 구글 시트 연결 (약 5분)

URL을 넣지 않으면 **이 기기 단독 모드**로 동작합니다. 여러 기기에서 같은 데이터를 보려면 아래 순서대로 하세요.

1. **Google 스프레드시트**를 새로 만듭니다 (이름 예: `다시봄 POS`).
2. 메뉴 **확장 프로그램 → Apps Script** 를 엽니다.
3. `apps-script.gs` 내용을 **전부 복사해 붙여넣고 저장**합니다.
4. **배포 → 새 배포**
   - 유형: **웹 앱**
   - 다음 사용자로 실행: **나**
   - 액세스 권한: **모든 사용자**
   - `배포` → 권한 승인
5. 나온 **웹 앱 URL**(`.../exec`)을 복사합니다.
6. POS 관리자 → **동기화** → URL 칸에 붙여넣기 → **URL 저장** → **연결 테스트**.

`Products` `Orders` `Inventory` `StockLogs` `SyncLog` 시트는 첫 요청 때 자동으로 만들어집니다.

동기화 버튼:

| 버튼 | 하는 일 |
|---|---|
| 연결 테스트 | 시트에 닿는지, 품목·주문이 몇 건인지 확인 |
| 품목 시트로 저장 | 이 기기의 품목(+매입가)을 시트로 올림 |
| 품목 불러오기 | 시트의 품목으로 이 기기를 교체 (교체 전 자동 스냅샷) |
| 주문 전송 | 아직 안 올라간 주문만 전송 |
| 주문·재고 조회 | 시트의 주문·재고·이력을 내려받아 병합 |
| **재고 시트로 저장** | 이 기기의 **지점별 재고 + 아직 안 올라간 입출고 이력**을 시트로 올림 |
| **재고 불러오기** | 시트의 재고·이력을 내려받아 병합 (지점×품목 단위, 시트가 더 최신이면 그 값을 씀) |
| 전체 동기화 | 주문 전송 + 재고 전송 + 전체 조회를 한 번에 |
| 자동 동기화 | 켜 두면 30·60·120·300초마다 미전송 주문을 올리고 새 주문·재고를 내려받음 |

- `Inventory` 시트: `key`(지점ID|품목ID) · 지점 · 품목 · 현재고 · 안전재고 · 갱신시각 — **지점×품목 한 줄**로 upsert
- `StockLogs` 시트: 일시 · 지점 · 품목 · 구분(입고/출고/반품/손실/조정, 주문 건은 `출고(판매)`·`입고(주문취소)`) · 변동 · 변동후 · 사유 · 주문번호
- Apps Script `?action=all` 은 **품목·주문·재고·이력**을 한 번에 돌려주고, `?action=inventory` 는 재고·이력만 돌려줍니다. POS의 모니터링 `새로고침`은 이 주소를 씁니다.

## 5-2. 주문 확인서 이미지 저장 · 카톡 공유

주문 확인서 모달 하단의 **`이미지 저장 / 카톡 공유`** 버튼 하나로 확인서를 그림(PNG)으로 만들어 보냅니다.

- **외부 라이브러리·CDN을 쓰지 않습니다.** 브라우저에 내장된 HTML5 `<canvas>` 에 직접 그리므로 인터넷이 없어도 `pos.html` 파일 하나로 동작합니다(단독 실행 원칙 유지).
- 논리 폭 **420px**(카톡·모바일에서 보기 좋은 세로로 긴 영수증 비율)을 **3배(1260px 폭) 고해상도**로 그려 카톡에서 열어도 글자가 선명합니다.
- 좁은 폭에 맞춰 레이아웃을 다시 잡았습니다: 헤더는 로고·가게명 가운데 정렬, 주문 정보는 라벨 왼쪽/값 오른쪽, 긴 배송지·상품명은 띄어쓰기 기준으로 두 줄까지 나눠 적고, 입금 계좌·송금 링크는 라벨 아래에 값을 쌓습니다.
- 들어가는 내용: **다시봄 텔로미어 로고 · `다시봄 · ○○점`**(브랜드 컬러 `#5D3969` 딥 플럼 / `#9A71A8` 라일락 포인트), 주문번호 · 주문일시 · 판매 채널 · 결제 수단 · 고객명, 상품명·단가·수량·금액, 할인, **최종 합계**, 설정에 넣어 둔 **입금 계좌(은행·계좌번호·예금주)** 와 **송금 링크** 안내.
- **매입가·마진은 이미지에 절대 들어가지 않습니다** — 고객 화면과 같은 공개 정보만 사용합니다.
- 동작 순서
  1. 휴대폰이 이미지 공유를 지원하면(`navigator.canShare`) → **공유 시트**가 열려 카카오톡·문자·메일 등으로 바로 보냅니다.
  2. 지원하지 않거나 공유를 취소하면 → `다시봄_주문확인서_{주문번호}.png` 파일로 **즉시 다운로드**합니다. (Chrome은 다운로드 폴더에 저장되고, 알림을 눌러 카톡으로 보낼 수 있습니다)
- 계좌·송금 링크를 설정하지 않았다면 그 안내 줄은 이미지에서 빠지고 이미지 높이도 그만큼 줄어듭니다.

## 5-1. 입금 계좌 · 송금 링크

관리자 → **설정** → **입금 계좌 · 송금 링크** 에서 네 칸을 넣고 `저장`합니다.

| 칸 | 예 | 쓰이는 곳 |
|---|---|---|
| 은행명 | 국민은행 | 확인서·복사본의 계좌 안내 |
| 계좌번호 | 123-45-6789012 | 확인서 표시 + `계좌번호 복사`(숫자만 복사) |
| 예금주 | 다시봄 담당자 | 확인서·복사본에 `(예금주 …)` 로 표시 |
| 간편 송금 링크 | `https://toss.me/…`, `https://link.kakaopay.com/…` | `송금 링크로 바로 보내기`(새 탭) · 복사본에 주소 |

- 값이 비어 있으면 확인서·복사본에 아무것도 나오지 않습니다(입력한 것만 표시).
- **송금 링크는 `https://` 주소만** 통과합니다. `http://`, `javascript:` 같은 주소는 저장해도 확인서·복사본에 나오지 않고 버튼도 생기지 않습니다.
- 계좌·링크는 고객에게 보여 주는 **공개 결제 정보**라서 공개 설정(localStorage)에 저장되고, 백업·복원에도 함께 들어갑니다. (실제 돈이 오가는 것은 아니며, POS는 안내 문구만 보여 줍니다.)

## 6. 데이터·보안

- 상품·주문·**지점·재고·입출고 이력**·설정은 **이 브라우저의 localStorage** 에 저장되고, 구글 시트를 연결하면 같은 값이 여러 기기에 나뉩니다.
- 배포 파일에는 **검색엔진 차단**을 이중으로 걸어 두었습니다 — `robots.txt` `Disallow: /` + HTML `<head>` 의 `<meta name="robots" content="noindex, nofollow">`. 관리자 화면·판매원 잠금은 그대로 동작합니다.
- **매입가·마진·PIN 해시·판매원 비밀번호 해시**는 고객 화면이 쓰는 저장소와 **분리된 저장소**에 들어가고, 고객 화면·영수증에는 전달되지 않습니다.
- 관리자 화면은 PIN 인증 뒤에만 만들어지고, **판매원 잠금이 풀리기 전에는 판매 화면 자체가 만들어지지 않습니다**(품목·가격·주문이 DOM에 없음).
- PIN·판매원 비밀번호는 화면 잠금용입니다. **페이지 소스는 누구나 읽을 수 있으므로**(특히 공개 주소로 배포한 경우) 데이터 암호화로 기대하지 마세요. 실제 매입가·주문은 브라우저 저장소에만 있고 배포 파일에는 들어 있지 않습니다.
- PIN은 화면 잠금용입니다. 파일을 아는 사람은 코드를 읽을 수 있으니, **고객에게 이 파일을 넘기지 말고 판매자 기기에서 고객 화면을 보여 주세요.**
- `설정 → 전체 백업(JSON)` 으로 주기적으로 백업하세요. 백업 파일에는 **매입가가 들어 있으니** 안전하게 보관하세요.
- 시트의 `Products` 에도 매입가가 저장됩니다. **시트 공유는 하지 마세요.**

## 8. 문제 해결

| 증상 | 확인 |
|---|---|
| 화면이 하얗다 | 브라우저에서 자바스크립트가 켜져 있는지, 파일이 온전히 복사됐는지 확인 |
| 이미지가 안 보인다 | 오프라인이거나 사내망에서 `cdn.gcoopm.com` 이 막힌 경우 — 자동으로 SVG 카드가 표시됩니다 |
| 주문이 다른 기기에 안 보인다 | 두 기기에 **같은 웹 앱 URL**이 저장돼 있는지, `자동 동기화`가 켜져 있는지 확인 |
| 동기화 실패 | 배포 설정의 **액세스 권한: 모든 사용자**, URL이 `/exec` 로 끝나는지 확인 |
| 관리자 PIN을 잊었다 | 복구할 수 없습니다. 백업이 있으면 `설정 → 백업 복원` 후 PIN을 다시 정하세요 |
| 판매원 비밀번호를 잊었다 | 판매원 칸에서는 복구되지 않습니다. 관리자 PIN으로 들어가 `설정 → 판매원 오픈 잠금`에서 다시 정하세요 |
| 매번 비밀번호를 묻는다 | 새 탭·새 창은 다시 묻는 것이 정상입니다. 같은 탭에서 새로고침하면 묻지 않습니다(브라우저가 sessionStorage를 막으면 매번 물을 수 있습니다) |
| CSV가 글자 깨짐 | 엑셀에서 "UTF-8 CSV"로 열기 (파일 맨 앞에 BOM을 넣어 두었습니다) |
| 입력한 데이터가 사라진다 | 브라우저가 `file://` 저장을 막은 경우입니다. Chrome으로 열거나, 구글 시트 동기화를 함께 쓰세요 (화면은 그대로 동작합니다) |
| 재고가 안 맞는다 | 관리자 → **재고**에서 그 **지점**을 골라 현재고를 확인하세요. 지점마다 따로 셉니다. 재고 실사는 `조정`으로 맞추면 됩니다 |
| 판매했는데 재고가 안 줄었다 | 그 주문이 **이 기기에서** 만들어졌는지 확인하세요. 다른 지점 기기에서 낸 주문은 모니터링 `새로고침`(재고 불러오기) 후에 반영됩니다 |
| 모니터링에 다른 지점이 안 보인다 | 동기화 탭에서 **URL 저장 → 연결 테스트**로 시트에 닿는지 확인하고, 모니터링의 `↻ 새로고침`을 누르세요. 시트 미연결이면 화면 위에 `현재 기기 데이터 기준` 안내가 나옵니다 |
| 상품 상세에 '제품 설명서 보기'가 없다 | `leaflet-data.js` 가 `pos.html` 과 **같은 폴더**에 있는지 확인하세요. 파일이 없으면 POS는 그대로 동작하고 설명서 버튼만 나오지 않습니다 |
| 설명서 이미지가 늦게 뜬다 | 상세 이미지가 품목당 최대 66장이라 스크롤하는 만큼 지연 로딩됩니다(정상). 사내망에서 `cdn.gcoopm.com` 이 막히면 그 이미지만 숨겨집니다 |
